Command Basics

Start here if commands are new to you.

Getting started

/help/help teleport/help give

Commands require the appropriate permissions/cheats for your world or server.

Command structure

/command target arguments

Most commands follow a command name, followed by a target and additional arguments. Always check your exact Minecraft version because syntax changes over time.

Chat shortcuts

Press Tab to autocomplete many commands, players, coordinates, and IDs. Use the up arrow to recall previous commands.

Permissions

In single-player, enable cheats when creating the world or temporarily open the LAN menu and enable cheats. Servers may use operator permissions.

Target Selectors

Basic selectors

@s — yourself @p — nearest player @a — all players @r — random player @e — all entities

Useful selector filters

@e[type=minecraft:zombie] @e[type=minecraft:item] @a[distance=..10] @a[name=Steve] @e[limit=1,sort=nearest]

Exact selector arguments differ between Java and Bedrock.

Relative coordinates

~ ~ ~ current position ~1 ~ ~ one block east ~ ~5 ~ five blocks up ~ ~ ~-10 ten blocks south

Local coordinates

^ ^ ^ ^ ^ ^5

Local coordinates are relative to the executor's facing direction and are especially useful for command-machine builds.

Command Blocks

Get a command block

/give @s minecraft:command_block 1

Impulse

Runs once when powered. Great for buttons, levers, traps, doors, and one-time actions.

Repeating

Runs repeatedly while active. Useful for clocks, detection systems, timers, and continuous effects.

Chain

Runs after the previous command block in a chain. Use it to build multi-step command systems.

Always Active

Removes the need for a redstone power signal. Useful for repeating and chain systems.

Conditional

Runs only when the preceding command block succeeds. Useful for branching command logic.

Safety tip: Test command machines in a copy of your world first. Broad selectors such as @a and @e can affect a lot of entities.

Command Automation Ideas

Automatic welcome

Repeating block detects nearby players, followed by chain blocks for a title, message, and effect.

Mob arena

Use /summon, selectors, effects, scoreboards, and conditional chains to create rounds.

Countdowns

Use scoreboard values and repeating/chain command blocks to display a countdown.

Custom shops

Use item detection, scores, commands, and NPCs/entities to create a command-powered shop.

Java Edition vs Bedrock Edition

Java Edition

Java generally has extensive command, datapack, function, and technical-building capabilities. Syntax can differ significantly from Bedrock.

Use the Java filter above when browsing edition-specific notes.

Bedrock Edition

Bedrock runs across many platforms and has its own command syntax, selector arguments, components, and behavior.

Always verify a command against your Bedrock version.

Why commands fail

A command copied from a different edition or an older/newer version may be invalid even if it looks correct.

Troubleshooting

“Unknown command”

Check spelling, edition, version, permissions, and whether cheats/operator access are enabled.

“Incorrect argument”

Use Tab completion and /help command. Check every argument in the order shown by your game.

Command works but affects nothing

Check the target selector, coordinates, distance, entity type, and whether the target actually exists.

Command block does nothing

Check power/Always Active, command text, conditional mode, chain direction, and command-block permissions.

Teleport went somewhere weird

Remember that ~ means relative coordinates. Check whether the command is executing from a player, command block, or another entity.

Need the exact syntax?

Use the in-game /help command and Tab completion for the exact command syntax supported by your installed version.
